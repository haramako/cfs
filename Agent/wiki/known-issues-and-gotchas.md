# 既知の不具合と落とし穴

コードを読んで見つけたもの（2026-10-25 時点、未修正）。修正したらこの記事から消すこと。表のファイル名は特記がなければ `internal/cfs/` 基準。

## 挙動上の注意

- **0 バイトのデータ**: 無圧縮・無暗号の空ファイル（`.raw` などの空ファイル）はデータも 0 バイトになる。2026-10-25 から、ほかと同じくキャビネットに置き、GC の参照（`Manifest.DataHashes`）と `ls --verify`（`ExistsAll`）でも普通に扱う。取得だけは、ハッシュが空の SHA-256 なら取りに行かずに空にする（`Downloader.Fetch`）。以前は、昔の S3 ライブラリ（goamz 系の `bucket.Put`）が 0 バイトでエラーになったため置いていなかった。aws-sdk-go-v2 では Put / Get / List とも問題ないことを実 S3 で確認済み
- **除外ルール**（`exclude.go`）: `DefaultExcludes`（`.*` `#*` `*~`）の後に `.cfsenv` の `Exclude` を続けた、`.gitignore` と似たパターン。後のものほど優先（`!` で戻せる）。外したフォルダは `SkipDir` するので、中のものは戻せない（git と同じ）。パスは `upload` に指定したフォルダからの相対パス（`filepath.Rel`。末尾の区切りがあっても正しい）。ファイルを直接指定したときはパターンを当てない。2026-10-25 に、ハードコードの `.meta` `.manifest` `.tmx` と、パス全体に `filepath.Match` を当てていて直下にしか効かなかった `ExcludePatterns`（`*.vdat` `cfs` など）をやめて置き換えた。以前は `.` で始まるフォルダの中身がアップロードされていたが、今はフォルダごと外れる
- **マニフェストはスナップショット**: `upload` は今回見つからなかったファイルをマニフェストから消す。複数ディレクトリを 1 回で上げると、各ルートからの相対パスがキーになるので同名パスは衝突する
- **`sync` は既定では出力先の余分なファイルを消さない**。`--delete` で、`Sync` が全部うまくいった後に `Downloader.RemoveUnlisted` が一覧にないファイルと空になったフォルダを消す（2026-10-25。既定で消さないのは、出力先を間違えたときの被害が大きいため。rsync や aws s3 sync と同じ）。比較は `pathKey`（NFC、Windows と macOS では小文字にそろえる。大文字だけ違う既存のファイルに書き出すと名前が残るので、それを消さないため）。また全ファイルを毎回書き直す（データ取得はキャッシュされる。8 並列）
- **ダウンロード側の鍵**: マニフェストは `decodeManifest` で圧縮・暗号化をデータから判断して読むので、`Compress` は一致していなくてよい（2026-10-25 から）。暗号化しているなら鍵は必要
- **無圧縮拡張子はハードコード**: `.ab` `.raw` `.pbx` `.mp4`（`Client.attribute`）。`.ab` は実行時の復号コストのため意図的に無暗号（オーナー確認済み）
- **S3**: リージョンは `.cfsenv` の `S3Region` → HeadBucket の `x-amz-bucket-region`（匿名で問い合わせる）→ `AWS_REGION` / プロファイル → `ap-northeast-1` の順（`newS3Storage`）。`Exists` は 403 も「ない」扱い（ListBucket 権限がないと 404 が 403 になるため）。`Put` の既存確認は ListObjectsV2（前方一致なので、キーが完全一致するかも確かめている）。リクエスト・レスポンスともチェックサムは「必要な場合のみ」（中身はハッシュで確かめる）
- アップロードに失敗したら、`Client.Finish` はマニフェストを置かずにエラーを返す（不完全なマニフェストを置かないため。2021-03 からの意図。以前は panic で止めていた）
- **GC の安全性の前提**: 「マニフェストが残っている間はその中身を消さない」ことに `upload` の手元キャッシュの信用が依存している（`Manifest.ValidateCache`）。`RunGC` の手順を変えるときはこの前提を崩さないこと。詳しくは `../discussions/2026-10-25-garbage-collection-plan.md` の追記
- **暗号化の IV は中身から決まる**（`crypt.go`。重複の排除のため）。同じ鍵で同じ中身なら同じ暗号文になるので、「同じ中身かどうか」は暗号文から分かる（内容アドレス方式である以上、ハッシュからも分かるので許容）

## 2026-10-25 に直したもの（参考）

- `cfs http` の XSS、panic、localhost 固定、毎回のマニフェスト取得（`cfs serve` として作り直した）

- `FileStorage` の既存確認が常に失敗して上書きしていた
- `encode` が引数の鍵を無視していた／IV が全ファイル共通だった（形式 v2 で暗号化を作り直した）
- `Manifest.Parse` の列数チェックの誤り（形式 v2 で 7 列ちょうどを要求）
- `pack.Parse` が `io.ReadFull` を使っていなかった
- `cmd_patch.go` が `pack.Patch` のエラーを無視していた
- パックのパスが 255 バイトを超えると、長さが 1 バイトに切り詰められて壊れていた（作るときにエラーにした）。`unpack -o` が `..` や絶対パスでフォルダの外に書けた
- Windows で `file://` から取得できなかった
- `config.go` のキャッシュの場所の関数が変数をシャドーし、`~/.cfs_setting` を毎回読み直していた（設定を `Config` にしたときに `~/.cfs_setting` ごと消した）
- CLI が失敗しても終了コードが 0 のことがあった／エラーが panic のスタックトレースや標準出力に出ていた（エラーを返して、`main` で標準エラーに出し終了コード 1 にした）
- `--filter-cmd` の中で panic するとプロセスごと落ちた。引用符で空白を含む引数を渡せなかった
- `pack.NewPackFileFromDir` がパスを文字数で切っていたため、`cfs pack out.tp .` や末尾に区切りのあるフォルダで、パスが壊れていた（`a.txt` → `txt`）。`filepath.Rel` に直した
