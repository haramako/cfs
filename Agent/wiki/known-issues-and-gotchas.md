# 既知の不具合と落とし穴

コードを読んで見つけたもの（2026-10-25 時点、未修正）。修正したらこの記事から消すこと。表のファイル名は特記がなければ `internal/cfs/` 基準。

## 挙動上の注意

- **0 バイトのデータは置かない**: `Client.Upload` が 0 バイトのデータ（無圧縮・無暗号の空ファイル）をキャビネットに置かない。ダウンロード側は `Size == 0` のとき取得せずに空ファイルを作る（`Downloader.Sync` / `FetchAll` / `Fetch`）。GC も 0 バイトのものは参照として数えない（`Manifest.DataHashes`）。0 バイトに関する修正は何度も入っているので、ここを触るときは S3 での挙動も確認する
- **除外ルールが 2 系統ある**: `Client.AddFiles` にハードコードされたもの（名前が `.` / `#` で始まる、`~` で終わる、拡張子 `.meta` `.manifest` `.tmx`）と、`ExcludePatterns`（`.*` `*.vdat` `cfs` `*.meta` `*.tmx`）。後者は `filepath.Match` をパス全体に当てているため、`*` がディレクトリ区切りにマッチせず、フォルダ引数なし（ルートが `.`）で実行したときの直下にしか効かない（`cfs upload src` のときは `src/x.vdat` も対象になる。実測済み）
- **`.` で始まるディレクトリの中身はアップロードされる**: ハードコード側の除外はディレクトリに対して `SkipDir` ではなく `nil` を返すので、`.hidden/x.txt` のようなファイルは対象になる（ゴールデンテストで確認済み）
- **マニフェストはスナップショット**: `upload` は今回見つからなかったファイルをマニフェストから消す。複数ディレクトリを 1 回で上げると、各ルートからの相対パスがキーになるので同名パスは衝突する
- **`sync` は出力先の余分なファイルを消さない**。また全ファイルを毎回書き直す（データ取得はキャッシュされるが、書き込みは逐次）
- **ダウンロード側の設定一致**: マニフェスト自体は `DefaultContentAttribute()` でデコードされるので、ダウンロード側の `.cfsenv` の `Compress` と鍵がアップロード側と一致していないとマニフェストが読めない（GC だけは `decodeManifest` で属性を推測して読む）
- **無圧縮拡張子はハードコード**: `.ab` `.raw` `.pbx` `.mp4`（`Manifest.GetAttribute`）。`.ab` は実行時の復号コストのため意図的に無暗号（オーナー確認済み）
- **S3**: リージョンは `.cfsenv` の `S3Region` → HeadBucket の `x-amz-bucket-region`（匿名で問い合わせる）→ `AWS_REGION` / プロファイル → `ap-northeast-1` の順（`newS3Storage`）。`Exists` は 403 も「ない」扱い（ListBucket 権限がないと 404 が 403 になるため）。`Put` の既存確認は ListObjectsV2（前方一致なので、キーが完全一致するかも確かめている）。リクエスト・レスポンスともチェックサムは「必要な場合のみ」（中身はハッシュで確かめる）
- アップロードワーカーはエラー時に panic する（不完全なマニフェストをアップロードしないための意図的な挙動。2021-03 の修正）
- **GC の安全性の前提**: 「マニフェストが残っている間はその中身を消さない」ことに `upload` の手元キャッシュの信用が依存している（`Manifest.ValidateCache`）。`RunGC` の手順を変えるときはこの前提を崩さないこと。詳しくは `../discussions/2026-10-25-garbage-collection-plan.md` の追記
- **暗号化の IV は中身から決まる**（`crypt.go`。重複の排除のため）。同じ鍵で同じ中身なら同じ暗号文になるので、「同じ中身かどうか」は暗号文から分かる（内容アドレス方式である以上、ハッシュからも分かるので許容）

## 不具合と思われるもの

| 場所 | 内容 |
|---|---|
| `config.go` `GlobalCacheDir` / `GlobalDataCacheDir` / `GlobalSettingPath` | 関数内で `globalCacheDir := ...` と書いておりパッケージ変数をシャドーしているため、結果がキャッシュされない。呼ぶたびに `InitDefaultSetting` が `~/.cfs_setting` を読み直す（`Fetch` はファイルごとに呼ぶので無駄が大きい）。直すとテストが使うホームフォルダの扱いが変わるので、2026-10-25 は見送った |
| `cmd/cfs/main.go` | `--setting` は未使用 |
| `internal/pack/pack.go` | パス長は 1 バイトなので 255 バイト超のパスは壊れる |
| `cmd/cfs/cmd_serve.go` | ファイルを一度メモリに読んでから返す（ストリーミング未対応）。大きいファイルを多数同時に返すとメモリを使う。計画では後回し |

## 2026-10-25 に直したもの（参考）

- `cfs http` の XSS、panic、localhost 固定、毎回のマニフェスト取得（`cfs serve` として作り直した）

- `FileStorage` の既存確認が常に失敗して上書きしていた
- `encode` が引数の鍵を無視していた／IV が全ファイル共通だった（形式 v2 で暗号化を作り直した）
- `Manifest.Parse` の列数チェックの誤り（形式 v2 で 7 列ちょうどを要求）
- `pack.Parse` が `io.ReadFull` を使っていなかった
- `cmd_patch.go` が `pack.Patch` のエラーを無視していた
- Windows で `file://` から取得できなかった
