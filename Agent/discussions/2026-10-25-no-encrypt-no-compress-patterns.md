# 暗号化・圧縮しないファイルを、ファイル名のパターンで設定できるようにする

**状態: 実装済み（2026-10-25）。**

## 背景

それまでは、拡張子 `.ab` `.raw` `.pbx` `.mp4` のファイルを決め打ちで「圧縮も暗号化もしない」にしていた（`Client.attribute`）。アップロードの対象から外すファイルを `.cfsenv` の `Exclude` で書けるようにした直後に、オーナーから「暗号化の対象にするかどうかのフィルタも、同じようにファイル名パターンで書けるようにして」と指示があった。

## 決定事項（エージェントが決めたこと）

- `.cfsenv` に `NoEncrypt`（暗号化しない）と `NoCompress`（圧縮しない）を足した。書き方は `Exclude` と同じ（`.gitignore` と似たパターン。`PathPatterns`）
  - 圧縮と暗号化を分けたのは、理由が違うため（圧縮は「もともと圧縮されていて小さくならない」、暗号化は「実行時の復号コスト」）
- フォルダのパターンに合えば、中のファイルすべてに効く（`MatchFile`）。選んだフォルダの中は `!` で戻せない（`.gitignore` と同じ）
- **既定は空**にした。`Exclude` で Unity 向けの決め打ち（`.meta` など）を設定に移したのと合わせ、Unity 向けの `.ab` などの決め打ちもやめた。何も書かなければ `.ab` も圧縮・暗号化する。以前と同じにするには、両方に `["*.ab", "*.raw", "*.pbx", "*.mp4"]` を書く（docs に書いた）
  - 使っているプロジェクトはまだないので、互換性は気にしない（memory の no-backward-compat-yet）
- 誤ったパターンは、どの設定のものか分かるエラーにする（`NoEncrypt: invalid pattern ...`）

## ついでに直したもの

- `docs/configuration.md` の「ダウンロードする側も同じ `Compress` と鍵が必要」は、マニフェストを属性の推測で読むようにした（同日のリファクタリング）ので古かった。必要なのは鍵だけ
