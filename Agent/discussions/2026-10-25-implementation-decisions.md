# 実装前の確認事項への回答

**状態: 決定（2026-10-25 オーナー回答）。** 実装待ちの計画を進める前に確認した事項と、その回答。各計画への影響もここにまとめる（経緯ログは書き換えないため、各計画の本文より**こちらが優先**）。

## 実装の順番（提案）

| # | 作業 | 依存・理由 |
|---|---|---|
| 1 | GCS を外す | 依存なし。以降に直すストレージが減り、依存も軽くなる |
| 2 | 取得部分（`Fetcher`）の切り出し + Windows `file://` 修正 + 普通のパス | S3 直接取得と serve の性能改善の土台 |
| 3 | S3 のリージョン指定 | 4 の前に入れておくと、直接取得が最初から複数リージョン対応 |
| 4 | S3 から直接取得（既定にする） | 2 と 3 の上に乗る |
| 5 | 暗号鍵を環境変数で上書き | 依存なし |
| 6 | バケット → マニフェストに改名 | 7 の直前に、名前だけの変更として |
| 7 | **形式 v2**（`manifest/` への分離 + GC + タグ整理 + SHA-256 化 + 署名 + ファイルごとの IV） | 形式変更をまとめて1回にする（下記 1） |
| 8 | `cfs serve`（公開向けの修正 + 性能改善） | 2 の取得部分と 6 の名前を使う |

## 回答と、各計画への影響

1. **形式の変更はまとめてよい。** [GC の計画](2026-10-25-garbage-collection-plan.md) の `manifest/` への分離と、[暗号化の改善](2026-10-25-encryption-improvement-plan.md) の SHA-256 化・マニフェストへの署名（A）・ファイルごとの IV と鍵 ID（C）を、**「形式 v2」として一度に変える**。互換性は当面不要なので、旧形式を読む仕組みは作らない
2. **S3 直接取得を既定にしてよい。** [S3 直接 sync の計画](2026-10-25-s3-direct-sync-plan.md) の「`Url` 未指定時の挙動は変えない」は取り消す。**`Cabinet` が `s3://` で `Url` が空のときは、S3 から直接取得する**（バケットを非公開にできる）。S3 静的サイトの http URL は、`Url` で明示したときだけ使う。追加の相談は済んだので、実装に入ってよい
3. **Unity 側のクライアントライブラリは、オーナーが後で渡す**（場所を探してもらっている）。形式 v2 は cfs 側を先に進め、Unity 側は受け取ってから合わせる
4. **暗号鍵の環境変数は `CFS_ENCRYPT_KEY` / `CFS_ENCRYPT_IV`**（[計画](2026-10-25-encrypt-key-env-override-plan.md)）
5. **改名後の CLI は `upload --manifest` / `-m` と `pack-manifest`**（[改名の方針](2026-10-25-rename-bucket-to-manifest.md)）
6. **GC の保持期間の設定は、キャビネット上に置く**（`.cfsenv` は cfs が自動で書き換えない）
   - 妥当。保持期間は、そのキャビネットを使う全員と GC で同じ値でなければならない性質のもので、プロジェクトや人ごとの `.cfsenv` に置くと食い違いうる
   - なお、[新しい設計](2026-10-25-garbage-collection-plan.md)（前回のマニフェストの存在確認）では `upload` は保持期間を使わず、使うのは GC だけ
   - 例: キャビネットの `config`（JSON）に `{"retention": "30d"}` を置き、`cfs gc` が読む。設定するコマンド（`cfs cabinet config set retention 30d` など）を用意する。cfs が `.cfsenv` を書き換えることはない
   - 既定値 30 日、定期実行は GitHub Actions の `schedule` を想定（回答がなかったので提案どおりとし、実装時に再確認する）
7. **署名の秘密鍵の置き場所は後で考える。** 形式 v2 には署名の欄と検証の仕組みを入れ、鍵の置き場所（Secrets Manager、GitHub の Secrets など）は運用を始めるときに決める
8. **serve のタグ名は `A-Za-z0-9._-` に限り、`upload` で確かめる**（[公開サーバーの計画](2026-10-25-public-serve-plan.md)）。CI でブランチ名を使う場合は `/` を `-` に置き換えてもらう
9. **`.htm` を Shift_JIS で返す特別扱いはやめる**（拡張子から決まる Content-Type をそのまま使う）
10. **S3 のリージョンの設定名は `.cfsenv` の `S3Region`**（[計画](2026-10-25-s3-region-plan.md)）

## 未決のまま残るもの

- Unity 側のクライアントライブラリの場所（上記 3）
- serve を動かす場所（oauth2-proxy なので場所は問わない）
