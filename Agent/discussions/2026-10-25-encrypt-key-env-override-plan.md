# 暗号鍵の環境変数での上書きと認証方法の説明（計画）

**状態: 計画のみ。実装は未着手（オーナーの指示で記録だけしている）。**

## 背景

アップロード用の認証情報について「今の保存方法は標準的か」という相談があった。確認した結果は次のとおり。

- S3 / GCS の認証情報は、どちらも SDK 標準の読み込み順（AWS: 環境変数・`~/.aws`・SSO・IAM ロール、GCS: Application Default Credentials）に任せており、cfs 自身はトークンを保存していない。これは標準的
- 標準から外れているのは、**暗号鍵（`EncryptKey` / `EncryptIv`）を `.cfsenv` に直接書くしかない**点。`.cfsenv` はプロジェクトに置く設定なのでリポジトリにコミットされやすく、環境変数で上書きする手段がない
- 認証方法と必要な権限が、人間向けの説明に書かれていなかった

## 計画

1. **暗号鍵を環境変数で上書きできるようにする**
   - 例: `CFS_ENCRYPT_KEY` / `CFS_ENCRYPT_IV` が設定されていれば、`.cfsenv` の値より優先する
   - 読み込みは `internal/cfs/option.go` の `LoadDefaultOptions` の後で行う（`.cfsenv` → 環境変数 → コマンドラインの順に上書き）
   - CI では GitHub Actions の Secrets などから渡す想定
   - 変数名は実装時にオーナーと確認する
2. **認証方法の説明を書く**
   - 2026-10-25 に `docs/storage-backends.md` を作り、S3 / GCS の認証方法・必要な権限・CI での OIDC の使い方は記載済み
   - 1 を実装したら、`docs/configuration.md` の `EncryptKey` の説明に環境変数での指定方法を追記する

## 関連

- 暗号鍵はアセットを復号するクライアント側にも組み込まれるため、厳密な秘密ではなく難読化に近い性質がある。より良い方法（ファイル一覧への署名、未公開コンテンツの鍵を後から配る、ファイルごとの IV など）も相談したが、記録するかは未定
- S3 のリージョン指定を標準的にする案（`.cfsenv` での明示 → バケットからの自動判定 → `AWS_REGION` / プロファイル → `ap-northeast-1`）も相談したが、記録するかは未定
