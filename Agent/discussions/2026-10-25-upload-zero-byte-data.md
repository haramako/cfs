# 0 バイトのデータもキャビネットに置く

**状態: 実装済み（2026-10-25）。**

## 背景

オーナーから「0 バイトのデータを置かないのは S3 へのアップロードが失敗するからだが、失敗しないようにできるか」と聞かれた。

- 0 バイトの特別扱いは 2021-03（b859bd5 ほか）に入った。当時の S3 ライブラリ（goamz 系の `bucket.Put`）が、サイズ 0 だとエラーになったため（当時のコメント「size が 0 だとエラーになるため、送信しないようにしている」）
- S3 自体は 0 バイトのオブジェクトを受け付ける。今の aws-sdk-go-v2 で、テスト用のバケットに 0 バイトを Put / Exists / Get / List して、すべて問題ないことを確かめた

## 決定事項

- **0 バイトのデータも、ほかと同じく置く**（`Client.Upload` の特別扱いをやめる）
- **GC は 0 バイトのデータも参照として数える**（`Manifest.DataHashes`）。数えないと、置いた空のデータを消してしまう
- **`ls --verify`（`ExistsAll`）も普通に確かめる**
- **取得の近道は残す**: ハッシュが空の SHA-256 なら、取りに行かずに空にする（`Downloader.Fetch`）。中身がハッシュで決まる以上、正しく、通信も省ける
- `docs/format.md` の仕様も「置く。ただし取り出す側は取得しなくてよい」に変えた（Unity 側はどちらでも動く）

## 補足

0 バイトのデータになるのは、圧縮も暗号化もしない空のファイル（`.ab` `.raw` `.pbx` `.mp4` の空ファイル）だけ。圧縮・暗号化するとヘッダーが付くので 0 バイトにならない。中身が同じなのでキャビネットには 1 つしか置かれず、増えるリクエストはほぼない。
