# S3 のリージョンを標準的に指定できるようにする（計画）

**状態: 提案した案のとおりで計画として記録（2026-10-25 オーナー指示）。実装は未着手。**

## 背景

S3 のリージョンが `ap-northeast-1` に固定されており（`internal/cfs/s3_storage.go` の `config.WithRegion`）、`AWS_REGION` やプロファイルの `region` を指定しても使われない。標準的に指定できる方法がほしい。

## 方針

リージョンは使う人の環境ではなく**バケットに付いている属性**なので、上から順に見て最初に決まったものを使う。

| 優先順 | 指定方法 | 例 |
|---|---|---|
| 1 | `.cfsenv` で明示する | `"S3Region": "us-west-2"` |
| 2 | 指定がなければ、バケットのリージョンを自動判定する | HeadBucket を呼び、`x-amz-bucket-region` を読む |
| 3 | 判定できなければ、AWS 標準の設定を使う | 環境変数 `AWS_REGION`、`~/.aws/config` のプロファイルの `region` |
| 4 | それでもなければ既定値 | `ap-northeast-1` |

## この順番にする理由

- `AWS_REGION` は他のツールのために設定されていることが多い（例: `us-east-1`）。これを自動判定より優先すると、東京リージョンのバケットで `301 PermanentRedirect` になりうる
- `aws s3 cp` はリージョン違いのリダイレクトを自動で追いかけるが、Go の SDK はやらない。cfs で自動判定すると AWS CLI と同じ感覚で使える
- `x-amz-bucket-region` は、権限がなく 403 が返る場合にも付いてくるので、認証なしでも判定できる
- 明示指定の置き場所は、アップロード先の `Cabinet` の隣（`.cfsenv`）が自然。CLI フラグ（`--s3-region` など）はなくても困らない

## 合わせて直す箇所

- `Url` が空のときに使う S3 静的サイトのダウンロード URL も `ap-northeast-1` が埋め込まれているので、リージョンから組み立てる
  - 古いリージョンは `s3-website-<region>`（ハイフン）、新しいリージョンは `s3-website.<region>`（ドット）と書式が違う。ハイフンのリージョン（`us-east-1`、`us-west-1`、`us-west-2`、`ap-northeast-1`、`ap-southeast-1`、`ap-southeast-2`、`eu-west-1`、`sa-east-1` など）の対応表をコードに持つ
- [S3 から直接 sync する計画](2026-10-25-s3-direct-sync-plan.md) は同じ S3 クライアントを使うので、リージョンの決め方を先に入れておくと、直接 sync も最初から複数リージョンに対応できる
- テスト: S3 の偽サーバーテストに、HeadBucket の結果で使うリージョンが変わることと、静的サイト URL の書式を足す

## 採らなかった案

- `Cabinet` の URL に書く（`s3://my-bucket?region=us-west-2`）: S3 の標準的な書き方ではない。URL のパス部分も今は無視しているので、URL の扱いの見直しは後回しにする

## 互換性

当面は互換性を気にしなくてよい（2026-10-25 オーナー指示）。優先順 4 の既定値 `ap-northeast-1` は、既存の利用者のためではなく、判定できないときの最後の手段として残す。
