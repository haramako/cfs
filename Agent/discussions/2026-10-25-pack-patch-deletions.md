# パックファイルのパッチで、ファイルの削除を表せるようにする

**状態: 実装済み（2026-10-25）。**

## 背景

`cfs patch 元.tp 新.tp 出力.tp` は「追加・変更」だけをまとめ、`元.tp` にあって `新.tp` にないファイル（削除）を表せなかった。オーナーから「削除対応をさせて」と指示があった。

## 選択肢

- A. ファイル一覧の後に「消すファイルの一覧」を足し、形式の版を 3 に上げる
- B. ファイル一覧の中に、削除の印（サイズ 0・ハッシュが全部 0 など）のエントリを入れる

B は形式の構造が変わらないが、知らない読み手は削除を空のファイルとして書いてしまい、気づけない。A は版が上がるので、古い読み手は版の確認でエラーになり、気づける。**A にした**（互換性は当面不要、memory の no-backward-compat-yet）。

## 決定事項（エージェントが決めたこと）

- 形式 3: 「一覧のサイズ」が、ファイル一覧と消すファイルの一覧を合わせたバイト数になる。消すファイルの一覧は、数（uint32）とパス（長さ uint8 + UTF-8）の並び。ふつうのパックでは 0 個
- `pack.PackFile.Deleted` に消すパスを持つ。`pack.Patch` が、`base` にあって `current` にないパスを入れる（パスの順）
- パッチを当てるのは `unpack -o`。追加・変更を書いた後、`Deleted` のパスを出力先から消す（ないものは無視）
- `unpack` の一覧表示では `パス<TAB>deleted` と出す
- `--filter-cmd` はエントリと消すパスの両方を絞る
- ついでに直したもの: 255 バイトを超えるパスは作るときにエラー（以前は黙って壊れた）。`unpack -o` は `..` や絶対パスをエラーにする（消す処理が入るので、フォルダの外を消せないようにした。書き込みも同じ）。`Pack` の `fn` 経路でサイズが合わないときにエラーを返していなかった

## 残り

- パックファイルを読む側（Unity など）があれば、形式 3 への対応が必要
