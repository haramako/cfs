# 制限と注意点

## マニフェストはスナップショット

`upload` は、そのときのフォルダの中身をそのまま記録します。前回あって今回なくなったファイルは、新しいマニフェストからは消えます（キャビネットからは、どこからも使われなくなった後の `gc` で消えます）。

複数のフォルダを1回の `upload` で指定すると、それぞれのフォルダからの相対パスで記録されます。同じ相対パスのファイルがあると、どちらか一方だけが残ります。

## タグの名前

タグに使える文字は `A-Za-z0-9._-` だけです。CI でブランチ名（`feature/foo`）をタグにする場合は、`/` を `-` に置き換えるなどしてください。

## `sync` は出力先を掃除しない

`sync` は、マニフェストにあるファイルを書き出すだけです。出力先にある、マニフェストにないファイルは消しません。完全に一致させたいときは、空のフォルダに `sync` してください。

## ダウンロード側も同じ圧縮・暗号化の設定が必要

マニフェスト自体が、`.cfsenv` の `Compress` と暗号化の鍵で圧縮・暗号化されています。ダウンロードする側の設定がアップロードした側と違うと、マニフェストが読めません。

## GC

- 使われなくなった中身が実際に消えるまでには、数回の `gc` が必要です（2回続けて候補になったものだけを消し、マニフェストを先に、中身を後の回で消すため）
- タグを消さない限り、そのタグのマニフェストと中身は消えません。古いタグは `cfs tag rm` で消してください
- 手元のダウンロードのキャッシュ（[キャッシュのフォルダ](configuration.md#手元のキャッシュ)の `data/`）は、`gc` では掃除されません。大きくなったら手で消してください

## 形式の互換性

キャビネットの形式は v2 です。以前の形式（v1）のキャビネットは読めないので、アップロードし直してください（[キャビネットの形式](format.md)）。

## ストレージごとの制限

- `s3://` で、バケット名の後ろのパスは無視されます

## パックファイル

- パスは 255 バイトまで、パックファイル全体は 4GB 未満です
- `patch` はファイルの削除を表せません
