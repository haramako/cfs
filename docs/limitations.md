# 制限と注意点

## アップロードの対象から外れるファイル

次のファイルは、`upload` のときに自動で対象から外れます。

- 名前が `.` で始まるファイル（例: `.DS_Store`）
- 名前が `#` で始まるファイル、`~` で終わるファイル（エディタの一時ファイルやバックアップ）
- 拡張子が `.meta`、`.manifest`、`.tmx` のファイル
- フォルダを指定せずに（今のフォルダを対象に）実行したときだけ、その直下にある `*.vdat` と `cfs`。`cfs upload src` のようにフォルダを指定したときは外れません

注意:

- **名前が `.` で始まるフォルダの中のファイルは、対象になります。** 例えば `.hidden/x.txt` はアップロードされます
- 対象外にするルールを、設定で変えることは今はできません

## ファイル一覧はスナップショット

`upload` は、そのときのフォルダの中身をそのまま記録します。前回あって今回なくなったファイルは、新しいファイル一覧からは消えます（キャビネットからは消えません）。

複数のフォルダを1回の `upload` で指定すると、それぞれのフォルダからの相対パスで記録されます。同じ相対パスのファイルがあると、どちらか一方だけが残ります。

## `sync` は出力先を掃除しない

`sync` は、ファイル一覧にあるファイルを書き出すだけです。出力先にある、一覧にないファイルは消しません。完全に一致させたいときは、空のフォルダに `sync` してください。

## ダウンロード側も同じ圧縮・暗号化の設定が必要

ファイル一覧自体が、`.cfsenv` の `Compress`、`EncryptKey`、`EncryptIv` で圧縮・暗号化されています。ダウンロードする側の設定がアップロードした側と違うと、ファイル一覧が読めません。

## キャビネットの古いデータは消えない

どのファイル一覧からも使われなくなった中身を、自動で消す仕組み（ガーベージコレクション）はありません。

## ストレージごとの制限

- **S3 のリージョンは `ap-northeast-1`（東京）に固定**です
- `s3://` で、バケット名の後ろのパスは無視されます

## パックファイル

- パスは 255 バイトまで、パックファイル全体は 4GB 未満です
- `patch` はファイルの削除を表せません
