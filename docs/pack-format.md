# パックファイル

パックファイルは、複数のファイルを1つにまとめる CFS 独自の形式です。キャビネット（内容アドレスのストレージ）とは別のもので、アプリに同梱したり、まとめて配ったりする用途を想定しています。拡張子に決まりはありません（コマンドの説明では `.tp` や `.cfspack` を使っています）。

## コマンド

| コマンド | 内容 |
|---|---|
| `cfs pack 出力.tp フォルダ` | フォルダの中の全ファイルをまとめます。`upload` と違って、ファイルを対象から外すルールはありません |
| `cfs pack-manifest ロケーション 出力.tp` | キャビネット上のファイル一覧の中身をダウンロードして（8並列、失敗時は3回まで再試行）、まとめます |
| `cfs unpack 入力.tp` | 中身の一覧（パス、サイズ、ハッシュ）を表示します。パッチで消すファイルは `パス<TAB>deleted` と表示します |
| `cfs unpack 入力.tp -o 出力先フォルダ` | 展開します。パッチなら、消すファイルを出力先から消します |
| `cfs patch 元.tp 新.tp 出力.tp` | `新.tp` のうち、`元.tp` にないファイルと中身が違うファイルをまとめ、`元.tp` にあって `新.tp` にないファイルを「消すファイル」として記録します |

`pack`、`pack-manifest`、`unpack` では `--filter-cmd` でファイルを絞り込めます（[コマンド](commands.md#ファイルの絞り込み)）。

パッチを当てるには、`元.tp` を展開したフォルダに、パッチを `unpack -o` で展開します。追加・変更したファイルが書かれ、消えたファイルが消され、`新.tp` を展開したのと同じになります。

```
cfs unpack -o app base.tp
cfs patch base.tp next.tp patch.tp
cfs unpack -o app patch.tp    # app は next.tp を展開したのと同じになる
```

`unpack -o` は、出力先のフォルダの外を指すパス（`..` を含むものや絶対パス）があればエラーにします。

## 形式

数値はすべてリトルエンディアンです。

```
ヘッダー          3 バイト   'T' 'P' バージョン（今は 3）
一覧のサイズ      uint32     下の「ファイル一覧」と「消すファイルの一覧」を合わせたバイト数
ファイル一覧:
  ファイル数      uint32
  各ファイル:
    パスの長さ    uint8      パスは最大 255 バイト
    パス          UTF-8、区切りは '/'
    位置          uint32     パックファイルの先頭からの、データの位置
    サイズ        uint32
    ハッシュ      32 バイト  元のファイルの SHA-256
消すファイルの一覧:          パッチで消すファイル。ふつうのパックでは 0 個
  ファイル数      uint32
  各ファイル:
    パスの長さ    uint8
    パス          UTF-8、区切りは '/'
データ            各ファイルの中身を、パスの順に並べたもの
```

- ファイルと消すファイルは、それぞれパスの順に並びます
- 読む側は、自分が扱えない版（今は 3 以外）のパックファイルをエラーにしてください。版 2 には「消すファイルの一覧」がありません
- 255 バイトを超えるパスは、パックファイルを作るときにエラーになります
- 中身は**圧縮も暗号化もしない、元のままのデータ**です。キャビネットの圧縮・暗号化の設定は関係しません
- 位置とサイズが uint32 なので、パックファイル全体を 4GB 未満にする必要があります
- ファイル一覧だけを読めば、各ファイルの位置が分かるので、必要なファイルだけを読み出せます
