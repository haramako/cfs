# キャビネットの形式（v2）

キャビネットの中身の決まりです。cfs 以外（ゲームのクライアントのライブラリなど）からキャビネットを読むときの仕様として使えます。

数値の表記は 10 進、ハッシュはすべて **SHA-256 の小文字 16 進表記（64 文字）** です。

## 配置

| 場所 | 中身 | 変わるか |
|---|---|---|
| `data/<h[0:2]>/<h[2:]>` | ファイルの中身（圧縮・暗号化後）。`h` はこのデータのハッシュ | 変わらない |
| `manifest/<h[0:2]>/<h[2:]>` | マニフェスト（圧縮・暗号化後）。`h` はこのデータのハッシュ | 変わらない |
| `tag/<名前>` | マニフェストのハッシュ（64 文字のテキスト） | 上書きされる |
| `config.json` | キャビネットの設定（`{"retention": "30d"}`） | 上書きされる |
| `gc/candidates.json`、`gc/log/` | GC の状態と記録 | 上書きされる |

タグの名前に使える文字は `A-Za-z0-9._-` です。

**0 バイトのデータは置きません。** マニフェストに書かれたサイズが 0 のファイルは、取得せずに空のファイルとして扱います。

## データの取り出し方

1. `data/...` や `manifest/...` を取得し、**取得したバイト列の SHA-256 が場所のハッシュと一致するか確かめる**
2. 属性（後述）に暗号化があれば、復号する
3. 属性に圧縮があれば、zlib で展開する

マニフェスト自体の属性は、アップロードした側の設定で決まります（`Compress` が真なら圧縮、`EncryptKey` があれば暗号化）。読む側も同じ設定にしておく必要があります。

## マニフェスト

UTF-8 のテキストで、改行は `\n` です。

```
#cfs-manifest 2
<ハッシュ>\t<パス>\t<サイズ>\t<更新日時>\t<元のハッシュ>\t<元のサイズ>\t<属性>
...
#signature ed25519 <鍵 ID> <署名>
```

- 1 行目は必ず `#cfs-manifest 2`
- 2 行目からは 1 ファイル 1 行で、パスの順に並ぶ。列はタブ区切り
  - ハッシュ: `data/` に置いたデータ（圧縮・暗号化後）のハッシュ
  - パス: `/` 区切りの相対パス
  - サイズ: `data/` に置いたデータのバイト数
  - 更新日時: RFC 3339
  - 元のハッシュ、元のサイズ: 元のファイルのハッシュとバイト数
  - 属性: ビット 0 が圧縮、ビット 1 が暗号化（0〜3）
- `#` で始まる行は、`#signature` 以外は読み飛ばす
- 最後の `#signature` 行は、署名する場合だけ付く（後述）

## 暗号化

### 鍵の導出

設定の `EncryptKey`（16 文字以上の任意の文字列）から、HMAC-SHA256 で 3 つの値を作ります。

```
enc_key = HMAC-SHA256(key = EncryptKey, data = "cfs-encrypt-key")        … 32 バイト。AES-256 の鍵
iv_key  = HMAC-SHA256(key = EncryptKey, data = "cfs-iv-key")             … 32 バイト。IV を作る鍵
key_id  = HMAC-SHA256(key = EncryptKey, data = "cfs-key-id") の先頭 8 バイト
```

### 暗号化したデータ

```
1 バイト   バージョン（1）
8 バイト   key_id
16 バイト  IV
残り       AES-256-CTR(enc_key, IV) で暗号化したデータ
```

- `IV = HMAC-SHA256(key = iv_key, data = 暗号化する前のデータ)` の先頭 16 バイト。中身から決まるので、同じ鍵で同じ中身なら同じデータになり、重複の排除が効く
- 復号するときは、`key_id` で鍵を選ぶ。鍵を入れ替えた後も、古い鍵（`OldEncryptKeys`）を持っていれば読める
- 暗号化には改ざんの検出がない。改ざんはハッシュとマニフェストの署名で検出する

## 署名

- 方式は Ed25519
- 署名の対象は、マニフェストの先頭から `#signature` 行の直前まで（最後の改行を含む）の全バイト
- `#signature ed25519 <鍵 ID> <署名>` の鍵 ID は、公開鍵（32 バイト）の SHA-256 の先頭 8 バイトの 16 進表記。署名は base64
- 読む側に検証用の公開鍵（`VerifyKeys`）があれば、署名がない、鍵 ID が分からない、署名が合わないマニフェストは読まない

## 以前の形式（v1）との違い

互換性はありません。v1 のキャビネットは読めないので、アップロードし直してください。

- ハッシュが MD5（32 文字）から SHA-256（64 文字）に
- マニフェストが `data/` から `manifest/` に分かれ、先頭に `#cfs-manifest 2` が付いた
- 暗号化が AES-CFB（固定の IV）から、鍵 ID 付きの AES-256-CTR（中身から決まる IV）に。`EncryptIv` は不要になった
- マニフェストの署名と、ダウンロード時のハッシュの照合を追加
