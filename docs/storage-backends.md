# ストレージ

アップロード先（キャビネット）は `.cfsenv` の `Cabinet` に、URL か手元のパスで指定します。

| URL | ストレージ | 認証 |
|---|---|---|
| `file:///path/to/dir` または `./dir` などのパス | ローカルのフォルダ | 不要 |
| `s3://<バケット名>` | Amazon S3 | AWS の標準の認証（後述） |

今のところ、対応しているのはローカルのフォルダと Amazon S3 だけです。Google Cloud Storage（`gs://`）などは、今後対応する予定です。

`s3://` は、バケット名の後ろのパス（`s3://bucket/some/dir`）を今は無視します。キャビネットはバケットの直下に作られます。

## ダウンロード元

ダウンロード元は次のように決まります。

1. `.cfsenv` の `Url`（またはコマンドラインの `--url`）があれば、そこから読みます
2. なければ、**キャビネットから直接読みます**。S3 のバケットは公開しなくて構いません（S3 の認証で読みます）

| ダウンロード元 | 読み方 |
|---|---|
| 手元のパス、`file://` | ファイルを直接読みます |
| `s3://<バケット名>` | S3 の API で直接読みます（認証が必要） |
| `http://`、`https://` | 普通の HTTP(S) の GET で読みます（認証なし） |

ゲームのクライアントなど、認証情報を持たせられない相手に配るときは、S3 の前に CloudFront などを置いて HTTP(S) で公開し、その URL を `Url` に指定します。キャビネットの `data/` の下は中身が変わらないので、CDN で長くキャッシュできます。`tag/` の下は上書きされるので、キャッシュしないか、短くしてください。

## Amazon S3

認証には、AWS の標準の仕組みを使います。AWS CLI と同じ方法で設定できます。

- 環境変数: `AWS_ACCESS_KEY_ID`、`AWS_SECRET_ACCESS_KEY`（必要なら `AWS_SESSION_TOKEN`）
- 設定ファイル: `~/.aws/credentials`、`~/.aws/config`。環境変数 `AWS_PROFILE` でプロファイルを選べます
- SSO: `aws sso login` でログインしたプロファイル
- EC2、ECS、EKS の上: そのマシンやタスクの IAM ロールが自動で使われます
- GitHub Actions: `aws-actions/configure-aws-credentials` の `role-to-assume`（OIDC）を使うと、長く使うキーを保存せずに済みます

手元の PC では、長く使うアクセスキーをファイルに置くより、SSO を使う方法をおすすめします。

必要な権限は次のとおりです。

| 権限 | 用途 |
|---|---|
| `s3:ListBucket` | 同じ中身が既にあるかの確認（アップロード） |
| `s3:PutObject` | ファイルとタグのアップロード |
| `s3:PutObjectAcl` | アップロード時に `bucket-owner-full-control` の ACL を付けるため（ACL が無効なバケットでは不要な場合があります） |
| `s3:GetObject` | S3 から直接ダウンロードするとき |

### リージョン

S3 のリージョンは、次の順に決まります。

1. `.cfsenv` の `S3Region`（例: `"S3Region": "us-west-2"`）
2. 指定がなければ、**バケットのリージョンを自動で調べます**（認証なしで問い合わせるので、権限は要りません）
3. 調べられなければ、AWS の標準の設定（環境変数 `AWS_REGION`、プロファイルの `region`）
4. それもなければ `ap-northeast-1`（東京）

ふつうは何も設定しなくても、バケットのリージョンが使われます。`AWS_REGION` が他の用途で別のリージョンに設定されていても、バケットのリージョンが優先されます。

### 注意

- 0 バイトのファイルはアップロードしません。ダウンロードするときは、ファイル一覧の情報から空のファイルを作ります

## ローカルのフォルダ

ローカルや共有フォルダをキャビネットにできます。認証は不要です。試しに動かすときや、社内の共有フォルダで配るときに使えます。

URL ではなく、普通のパスでも書けます。`://` を含むものは URL、含まないものはパスとして扱います。

```json
{ "Cabinet": "./cabinet" }
{ "Cabinet": "C:\\work\\cabinet" }
{ "Cabinet": "file:///C:/work/cabinet" }
{ "Cabinet": "\\\\server\\share\\cabinet" }
```

- **相対パスの基準**: `.cfsenv` に書いた相対パスは、**`.cfsenv` があるフォルダ**が基準です。どこから `cfs` を実行しても、同じ場所を指します。コマンドラインの `--cabinet` や `--url` に書いた相対パスは、今いるフォルダが基準です
- **Windows の `\work` や `/work`**: 基準のフォルダがあるドライブのルートからのパスになります
- **Windows の `C:work` の形**（ドライブ名の直後に `\` がないもの）は、ドライブごとの「今のフォルダ」に左右されて分かりにくいので、エラーにしています。`C:\work` か相対パスで書いてください
- `file://` の URL で書く場合、相対パスは書けません（`file://` の決まりで、常に絶対パスです）。Windows では `file:///C:/work` のように、スラッシュを3本書いてからドライブ名を書きます
