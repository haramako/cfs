# コマンド

```
cfs [グローバルオプション] <コマンド> [オプション] [引数...]
```

`cfs -h` で一覧、`cfs help <コマンド>` で各コマンドの説明を表示できます。

コマンドのオプションは、引数の後ろにも書けます（`cfs upload src -t v1`）。グローバルオプションも、コマンドの後ろに書けます（`cfs upload -V src`）。

失敗したときは、標準エラーに `error: ...` を出し、終了コード 1 で終わります。CI やスクリプトからは、終了コードで成否を判断できます。

## グローバルオプション

| オプション | 既定値 | 内容 |
|---|---|---|
| `--verbose`, `-V` | | 詳しいログを表示します |
| `--config`, `-C` | `.cfsenv` | 設定ファイル |
| `--cabinet`, `-c` | | アップロード先の URL かパス（`.cfsenv` の `Cabinet` を上書き） |
| `--url` | | ダウンロード元の URL かパス（`.cfsenv` の `Url` を上書き） |
| `--force`, `-f` | | 手元のキャッシュを使わずに、全ファイルを調べ直してアップロードします |
| `--filter-cmd` | | 対象のファイルを絞り込むコマンド（[後述](#ファイルの絞り込み)） |
| `--help`, `-h` | | ヘルプを表示します |
| `--version`, `-v` | | バージョンを表示します |

## アップロード

### `upload`

```
cfs upload [-t タグ] [-m マニフェストの保存先] [-o ハッシュの出力先] [フォルダ...]
```

フォルダをアップロードします。フォルダを省略すると、今のフォルダ（`.`）が対象です。

| オプション | 内容 |
|---|---|
| `--tag`, `-t` | アップロードしたマニフェストにタグを付けます。使える文字は `A-Za-z0-9._-` です |
| `--manifest`, `-m` | 前回のマニフェストの保存先（手元のキャッシュ）。省略すると、手元のキャッシュ（[設定](configuration.md#手元のキャッシュ)）の `manifest/` に自動で作ります |
| `--output`, `-o` | アップロードしたマニフェストのハッシュを、このファイルに書き出します |

環境変数 `CFS_SIGNING_KEY` があれば、マニフェストに署名します（[設定](configuration.md#マニフェストの署名)）。

対象から外れるファイルと、外すファイルの指定は [設定](configuration.md#アップロードの対象から外すファイル) を見てください。

### `merge`

```
cfs merge [-o ハッシュの出力先] 出力タグ ロケーション [ロケーション...]
```

複数のマニフェストをまとめて、新しいマニフェストを作り、`出力タグ` を付けます。同じパスがあるときは、**後ろに書いたものが優先**されます。ファイルの中身はキャビネットに既にあるので、アップロードし直しません。

例: 共通のアセットとプラットフォーム別のアセットをまとめる

```
cfs merge ios common ios-only
```

## ダウンロード・確認

### `sync`

```
cfs sync [--delete] ロケーション 出力先フォルダ
```

マニフェストの全ファイルを、出力先フォルダに書き出します。中身はハッシュで照合してから書き出します。

- 既定では、出力先にある、一覧にないファイルは**消しません**
- `--delete` を付けると、書き出しが全部うまくいった後で、出力先にある一覧にないファイルと、それで空になったフォルダを消します。出力先をマニフェストと同じ中身にしたいときに使います。`--filter-cmd` で絞り込んだときは、絞り込んだ後の一覧にないものを消します。**出力先を間違えると、そのフォルダの中身を消してしまうので注意してください**
- Windows と macOS では、大文字と小文字だけが違う名前は同じファイルとして扱います（`--delete` で消しません）
- ファイルの書き込みは、途中で失敗しても壊れたファイルが残らない方法で行います

### `ls`

```
cfs ls [--verify] ロケーション
```

マニフェストの中身を、パス・ハッシュ・サイズ・更新日時の順で表示します。ハッシュとサイズは、圧縮・暗号化する前の元のファイルのものです。

`--verify` を付けると、各ファイルの中身がダウンロード元に本当にあるかを確認し、`ok` / `ng` を表示します。`ng` が1つでもあれば、終了コード 1 で終わります。

### `cat`

```
cfs cat ロケーション ファイルのパス
```

1つのファイルの中身を標準出力に表示します。主に確認用です。

### `config` / `setting`

今のアップロード先とダウンロード元（`config`）、キャッシュの置き場所（`setting`）を表示します。

### `serve`

```
cfs serve [--listen アドレス] [--tag-ttl 期間]
```

キャビネットの中身（HTML などのドキュメントやアーティファクト）をブラウザで見られる HTTP サーバーを起動します。`cfs upload -t report-123 out/` で上げたものを、`http://localhost:8000/report-123/` で見る、という使い方です。

| オプション | 既定値 | 内容 |
|---|---|---|
| `--listen` | `127.0.0.1:8000` | 待ち受けるアドレス |
| `--tag-ttl` | `30s` | タグが指すマニフェストを覚えておく時間。タグを上書きしてから反映されるまで、最大でこの時間かかります |

- `http://<ホスト>/<タグ>/<パス>` でファイルを返します。フォルダなら、`index.html` があればそれを、なければファイルの一覧を返します。末尾の `/` がないフォルダの URL は、`/` 付きにリダイレクトします（HTML の相対リンクが正しく解決されるように）
- タグの代わりにマニフェストのハッシュも使えます（`/<ハッシュ>/<パス>`）。この URL の中身は変わらないので、ブラウザや CDN に長くキャッシュされます
- サブドメインでタグを指定することもできます（`<タグ>.example.com`。ただし `cfs.` は特別扱いで無視します）
- `Content-Type` は拡張子から決めます。分からないものは `application/octet-stream` です。`.md` / `.markdown` / `.txt` は、ブラウザでそのまま読めるように UTF-8 のテキスト（`text/markdown` / `text/plain`）として返します（Markdown は整形されず、テキストのまま表示されます）
- 中身のハッシュを `ETag` にするので、変わっていなければ `304` を返します。途中からの取得（`Range`）にも対応しています
- ないファイルは `404` を返します。アクセスのログを標準エラーに出します（前段の oauth2-proxy が付ける `X-Forwarded-Email` があれば、その人のメールアドレスも出します）

#### 公開するとき

`cfs serve` 自身は**認証を持ちません**。インターネットに公開するときは、[oauth2-proxy](https://github.com/oauth2-proxy/oauth2-proxy) などの認証プロキシを前に置き、`cfs serve` は `127.0.0.1` だけで待ち受けてください。

```
cfs serve --listen 127.0.0.1:8000
oauth2-proxy --config=oauth2-proxy.cfg --authenticated-emails-file=emails.txt --upstream=http://127.0.0.1:8000/
```

- oauth2-proxy で Google ログインを使うには、Google Cloud で OAuth 同意画面（利用者の種類は「外部」）と OAuth クライアント ID を作ります。取引先などの Gmail アカウントも通せます
- 通すメールアドレスの一覧（`emails.txt`）は、公開しないリポジトリなどで管理してください
- サブドメインでタグを分ける場合は、oauth2-proxy の Cookie をサブドメイン全体で共有する設定（`--cookie-domain`、`--whitelist-domain`）と、ワイルドカードの証明書が必要です
- アップロードした HTML の JavaScript は、`cfs serve` と同じオリジンで動きます。パスでタグを分けると、あるアーティファクトの JavaScript から別のアーティファクトを読めます。見せる相手ごとに分けたい場合は、サブドメインで分けるか、キャビネットを分けてください

## キャビネットの管理

### `gc`

```
cfs gc [--dry-run] [--retention 期間]
```

どこからも使われなくなったマニフェストと中身を、キャビネットから消します。

- **残すもの**: すべてのタグが指すマニフェストと、保持期間（既定 30 日。`cfs cabinet config` で変更）内に作られたマニフェスト、およびそれらの中身
- **消すもの**: それ以外のマニフェストと、保持期間より古く、キャビネットに残っているどのマニフェストからも使われていない中身
- 消すのは、**前回の `gc` でも消す候補だったもの**だけです（2回続けて候補になったもの。前回から 1 時間以上あける必要があります）。アップロードの途中のものを消さないためです
- マニフェストを先に消し、その中身は後の回で消します。なので、使われなくなった中身が実際に消えるまでには、数回の `gc` が必要です
- 使われているマニフェストが1つでも読めないとき（鍵の設定が違うなど）は、何も消さずに止まります
- 消したものの一覧は、キャビネットの `gc/log/` に残ります

| オプション | 内容 |
|---|---|
| `--dry-run` | 何も消さず、消すはずのものを表示します |
| `--retention` | 保持期間を、今回だけ変えます（例: `14d`） |

定期的に（例: 1 日 1 回）実行してください。GitHub Actions の `schedule` などで動かせます。最初の数回は `--dry-run` で確かめると安心です。

### `tag`

```
cfs tag ls
cfs tag rm タグ [タグ...]
```

タグの一覧（名前、指しているマニフェストのハッシュ、更新日時）を表示します。`rm` はタグを消します。マニフェストと中身は、その後の `gc` で消えます。

### `cabinet init`

```
cfs cabinet init [--region リージョン] [--retention 期間] [--dry-run]
```

`.cfsenv` の `Cabinet`（または `-c`）のキャビネットを作ります。何度実行しても大丈夫です。

- **S3（`s3://<バケット名>`）の場合**
  1. バケットを作ります。リージョンは `--region` → `.cfsenv` の `S3Region` → `AWS_REGION` やプロファイルの設定 → `ap-northeast-1` の順で決めます。自分のバケットが既にあれば、そのまま使います。他の人が使っている名前ならエラーになります
  2. パブリックアクセスをすべてブロックします（cfs は S3 から直接読むので、公開は不要です）
  3. ACL を無効にします（オブジェクト所有者を「バケット所有者の強制」に）
  4. `config.json`（形式の版と保持期間）を置きます
  - バージョニングは有効にしません（GC で消しても容量が減らなくなるため）
- **手元のフォルダの場合**: フォルダを作り、`config.json` を置きます

| オプション | 内容 |
|---|---|
| `--region` | S3 のリージョン |
| `--retention` | GC の保持期間（例: `30d`）。省略すると、今の設定（なければ `30d`）のまま |
| `--dry-run` | 何もせず、何をするかを表示します |

管理者が一度だけ実行する想定です。必要な権限は `cfs cabinet policy admin` で表示できます。

### `cabinet policy`

```
cfs cabinet policy upload|download|gc|admin
```

S3 のキャビネットを使うのに必要な IAM ポリシーを、用途ごとに JSON で表示します。IAM のユーザーやロールにそのまま付けられます。

| 用途 | 内容 |
|---|---|
| `download` | `sync` や `serve` で読むだけ（`s3:GetObject`） |
| `upload` | `upload` と `merge`（読み込みも含む） |
| `gc` | `gc` と `tag rm`（削除を含む） |
| `admin` | `cabinet init`（バケットの作成と設定） |

### `cabinet config`

```
cfs cabinet config
cfs cabinet config set retention 14d
```

キャビネットの設定（`config.json`）を表示・変更します。今のところ設定できるのは `retention`（GC の保持期間）だけです。

### `keygen`

```
cfs keygen
```

マニフェストに署名するための鍵の組を作り、表示します。使い方は [設定](configuration.md#マニフェストの署名) を見てください。

## パックファイル

詳しくは [パックファイル](pack-format.md) を見てください。

| コマンド | 内容 |
|---|---|
| `cfs pack 出力.tp フォルダ` | フォルダをパックファイルにまとめます |
| `cfs pack-manifest ロケーション 出力.tp` | キャビネット上のファイル一覧の中身をダウンロードして、パックファイルにまとめます |
| `cfs unpack 入力.tp` | パックファイルの中身を一覧表示します |
| `cfs unpack 入力.tp -o 出力先フォルダ` | パックファイルを展開します |
| `cfs patch 元.tp 新.tp 出力.tp` | 2つのパックファイルの差分（追加・変更したファイルと、消えたファイルの一覧）を含むパックファイルを作ります |

## ファイルの絞り込み

グローバルオプションの `--filter-cmd` で指定します。`sync`、`merge`、`pack`、`unpack`、`pack-manifest` で使えます。

対象のファイルのパスを1行に1つずつ、指定したコマンドの標準入力に渡します。コマンドが標準出力に返した行のファイルだけを対象にします。

```
cfs --filter-cmd "grep ^sound/" sync v1 out
```

コマンドの文字列は、シェルを通さずに空白で区切って実行します。空白を含む引数は `"..."` か `'...'` で囲めます（`--filter-cmd '"C:/Program Files/filter.exe" sound'`）。パイプやリダイレクトは使えないので、複雑な条件はスクリプトにして呼び出してください。フィルターのコマンドが失敗した（終了コードが 0 以外の）ときは、cfs も失敗します。
