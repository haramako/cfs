# 設定

CFS の設定は2種類あります。ほかに、鍵やキャッシュの場所を環境変数で渡せます（後述）。

| ファイル | 場所 | 形式 | 内容 |
|---|---|---|---|
| `.cfsenv` | コマンドを実行するフォルダ（`-C` で変更可） | JSON | プロジェクトごとの設定。アップロード先、ダウンロード元、圧縮、暗号化、署名の検証など |
| `config.json` | キャビネットの中 | JSON | キャビネットごとの設定。GC の保持期間。`cfs cabinet config set` で変えます |

どちらも、なければ既定値で動きます。cfs が `.cfsenv` を書き換えることはありません。`.cfsenv` が JSON として読めなければエラーになります。

## `.cfsenv`

```json
{
  "Cabinet": "s3://my-bucket",
  "Url": "https://cdn.example.com/",
  "Compress": true,
  "VerifyKeys": ["GbcHHtfTyuXr3Ip1QxWGyIrZr2ee3DHkuEX9mZdWeEo="]
}
```

キーの大文字・小文字は区別しません。

| キー | 既定値 | 内容 |
|---|---|---|
| `Cabinet` | （空） | アップロード先。空のままキャビネットを使うコマンドを実行するとエラーになります。`s3://` や `file://` の URL か、手元のパス（相対パスは `.cfsenv` のあるフォルダが基準）。[ストレージ](storage-backends.md) を参照 |
| `Url` | （空） | ダウンロード元。URL か手元のパス。空ならキャビネットから直接読みます（[ストレージ](storage-backends.md) を参照） |
| `S3Region` | （空） | S3 のリージョン。空ならバケットから自動で調べます（[ストレージ](storage-backends.md#リージョン) を参照） |
| `Compress` | `true` | zlib で圧縮するか |
| `EncryptKey` | （空） | 暗号化の鍵。16 文字以上の任意の文字列（32 文字以上のランダムな文字列がおすすめ）。空なら暗号化しません。**環境変数 `CFS_ENCRYPT_KEY` で渡すのがおすすめ**（後述） |
| `OldEncryptKeys` | （空） | 鍵を入れ替えた後も、古い鍵で暗号化したデータを読むための鍵の一覧。環境変数 `CFS_OLD_ENCRYPT_KEYS`（カンマ区切り）でも渡せます |
| `VerifyKeys` | （空） | マニフェストの署名を確かめる公開鍵の一覧（後述） |
| `Recursive` | `true` | サブフォルダも対象にするか |
| `Flatten` | `false` | `true` にすると、フォルダ構成を捨ててファイル名だけで管理します |

コマンドラインの `--cabinet` / `-c` で `Cabinet` を、`--url` で `Url` を上書きできます。コマンドラインで書いた相対パスは、今いるフォルダが基準です。

### 環境変数

| 環境変数 | 内容 |
|---|---|
| `CFS_ENCRYPT_KEY` | `EncryptKey` を上書きします |
| `CFS_OLD_ENCRYPT_KEYS` | `OldEncryptKeys` を上書きします（カンマ区切り） |
| `CFS_SIGNING_KEY` | マニフェストに署名する秘密鍵。**環境変数でしか渡せません**（後述） |
| `CFS_CACHE_DIR` | 手元のキャッシュを置くフォルダ（[後述](#手元のキャッシュ)） |

環境変数は `.cfsenv` より優先され、`.cfsenv` がなくても使われます。`-V`（詳しいログ）で設定を表示するときも、鍵は `***` と伏せて表示します。

### 圧縮と暗号化

- 順番は **zlib 圧縮 → AES-256-CTR 暗号化** です。戻すときは逆の順番です
- `Compress` が `true` なら圧縮し、`EncryptKey` が空でなければ暗号化します
- 同じ鍵で同じ中身なら同じデータになるので、暗号化しても重複の排除が効きます
- ただし、拡張子が **`.ab`、`.raw`、`.pbx`、`.mp4` のファイルは、設定にかかわらず圧縮も暗号化もしません**。Unity の AssetBundle や動画のように、容量が大きく、もともと圧縮されているものだからです。特に AssetBundle は、クライアントで読み込むたびに復号すると実行時のコストが高いので、意図的に暗号化していません。今のところ、この拡張子の一覧は変更できません
- どのファイルを圧縮・暗号化したかはマニフェストに記録されるので、ダウンロードするときはファイルごとに正しく戻せます

**ダウンロードする側も、アップロードした側と同じ `Compress` と鍵が必要です。** マニフェスト自体が、これらの設定で圧縮・暗号化されているためです。

### 暗号鍵を `.cfsenv` に書かない

`EncryptKey` は秘密にしたい情報です。`.cfsenv` はリポジトリにコミットされやすいので、**環境変数 `CFS_ENCRYPT_KEY` で渡す**のがおすすめです。CI では GitHub Actions の Secrets などから渡します。

### 暗号鍵を入れ替える

1. 新しい鍵を `EncryptKey`（`CFS_ENCRYPT_KEY`）に、古い鍵を `OldEncryptKeys`（`CFS_OLD_ENCRYPT_KEYS`）に設定します
2. 以後のアップロードは新しい鍵で暗号化されます。古い鍵で暗号化したデータも、データに書かれた鍵 ID から古い鍵を選んで読めます
3. 古い鍵のデータがどのタグからも使われなくなり、GC で消えたら、`OldEncryptKeys` から外せます

鍵が漏れたときは、新しい鍵に入れ替えてからアップロードし直すと、それ以降のデータは新しい鍵で守られます。

### マニフェストの署名

マニフェストに署名しておくと、キャビネットや経路の途中でマニフェストを差し替えられても検出できます。中身はマニフェストに書かれたハッシュで照合するので、全体の改ざんを検出できます。

1. `cfs keygen` で鍵の組を作ります

   ```
   # Signing key: set to CFS_SIGNING_KEY on the uploading side. Keep it secret.
   CFS_SIGNING_KEY=...
   # Verify key: add to VerifyKeys in .cfsenv on the downloading side.
   "VerifyKeys": ["..."]
   ```

2. **アップロードする側**（CI など）の環境変数 `CFS_SIGNING_KEY` に秘密鍵を設定します。秘密鍵は Secrets などで管理し、リポジトリには置きません
3. **ダウンロードする側**の `.cfsenv` の `VerifyKeys` に公開鍵を入れます。公開鍵は知られても問題ないので、`.cfsenv` に書いてコミットして構いません

`VerifyKeys` があると、署名のないマニフェストや、知らない鍵で署名されたマニフェストは読みません。鍵を入れ替えるときは、新旧の公開鍵を両方 `VerifyKeys` に入れておけば、入れ替えの途中でも読めます。

## キャビネットの設定（`config.json`）

| キー | 既定値 | 内容 |
|---|---|---|
| `format` | （なし） | キャビネットの形式の版（今は `2`）。`cfs cabinet init` が書きます。cfs は、自分が扱えない版のキャビネットを読み書きせずにエラーにします。書かれていなければ今の版として扱います |
| `retention` | `30d` | GC の保持期間。この期間内に作られたマニフェストは、タグがなくても消しません（`30d`、`72h` のように書きます） |

```
cfs cabinet config                     # 表示
cfs cabinet config set retention 14d   # 変更
```

保持期間は、そのキャビネットを使う全員と GC で同じ値でなければならないので、`.cfsenv` ではなくキャビネットに置きます。

## 手元のキャッシュ

キャッシュは、OS のキャッシュフォルダの下の `cfs` に置きます。環境変数 `CFS_CACHE_DIR` で場所を変えられます（容量の大きい別のドライブに移したいときなど）。

| OS | 既定の場所 |
|---|---|
| Windows | `%LocalAppData%\cfs` |
| macOS | `~/Library/Caches/cfs` |
| Linux | `$XDG_CACHE_HOME/cfs`（なければ `~/.cache/cfs`） |

| 場所 | 内容 |
|---|---|
| `manifest/` | `upload` のときに使う、前回のマニフェストと、そのハッシュ（`.hash`）。アップロード先・今のフォルダ・対象フォルダの組み合わせごとに1つできます |
| `data/` | ダウンロードしたファイルの中身（圧縮・暗号化されたまま） |

どちらも消して構いません。消した場合、次回の `upload` は全ファイルを読み直し（中身が同じならアップロードはしません）、`sync` は中身をダウンロードし直します。

`upload` は、前回のマニフェストがキャビネットにまだあるかを確かめてから、キャッシュを使います。GC で消えていたら、キャッシュを使わずに全ファイルを調べ直します。

`upload` の `-m` で保存先を指定すると、`manifest/` の代わりにそこを使います。

`cfs config` で、今のアップロード先・ダウンロード元・キャッシュの場所を確認できます。
