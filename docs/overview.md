# 仕組み

## 用語

| 用語 | 意味 |
|---|---|
| キャビネット (cabinet) | アップロード先のストレージ全体。`s3://` か `file://` の URL、または手元のパスで指定します |
| マニフェスト (manifest) | 1回のアップロードで記録される「ファイル一覧」です。どのパスのファイルがどの内容（ハッシュ）かを持っています。以前は「バケット」と呼んでいましたが、S3 のバケットとまぎらわしいので改名しました |
| タグ (tag) | マニフェストに付ける名前です。git のブランチやタグのように、名前から最新のマニフェストを引けます。使える文字は `A-Za-z0-9._-` です |
| ロケーション (location) | コマンドで「どのマニフェストか」を指定する引数です。タグ名か、マニフェストのハッシュ（64桁の16進数）を書きます |

## 内容アドレスで保存する

CFS は、ファイルを**中身のハッシュ（SHA-256）をもとにした場所**に保存します。考え方は git のオブジェクトの保存方法とよく似ています。

```
<キャビネット>/
  data/
    c5/9548c3c5...      # ファイルの中身（ハッシュの先頭2文字/残り62文字）
  manifest/
    5c/e2d9f1d3...      # マニフェスト
  tag/
    v1                  # 中身はマニフェストのハッシュ（64文字のテキスト）
  config.json           # キャビネットの設定（GC の保持期間）
  gc/                   # GC の状態と記録
```

これにより、次のことができます。

- **同じ中身のファイルは1つだけ保存されます。** 別のパスでも、別のバージョンでも、別のプラットフォーム向けのファイルセットでも共有されます
- **一度アップロードした中身は、二度とアップロードしません。**
- **一度ダウンロードした中身は、二度とダウンロードしません。**
- **`data/` と `manifest/` の下は、同じパスのまま中身が変わることがありません。** そのため、CDN や HTTP プロキシで安全にキャッシュできます。`tag/` は上書きされるので、キャッシュしないでください

形式の細かい決まりは [キャビネットの形式](format.md) を見てください。

## アップロードの流れ（`cfs upload`）

1. 前回アップロードしたときのマニフェストを、手元のキャッシュから読み込みます。**そのマニフェストがキャビネットにまだあるかを1回だけ確かめ**、なければ（GC で消えていたら）キャッシュを使わずに全ファイルを調べ直します
2. 指定したフォルダの中を順に調べ、変更があったファイルだけを見つけます
   - 更新日時とサイズが前回と同じなら、ファイルを読まずに「変更なし」とします（ファイルシステムによる誤差を考えて、1秒までのずれは許します）
   - 読み込んだ結果、ハッシュが前回と同じなら、更新日時だけを記録し直します
3. 変更があったファイルを圧縮・暗号化して、32並列でアップロードします。既にキャビネットにある中身は送りません
4. 今回見つからなかったファイルは一覧から消えます。つまり、マニフェストは**そのフォルダの完全なスナップショット**です
5. マニフェスト自体もアップロードし（署名の鍵があれば署名します）、タグを指定していればタグをそのハッシュで更新します

変更がほとんどなければ、2回目以降のアップロードは一瞬で終わります。

## ダウンロードの流れ（`cfs sync`）

1. ロケーションがタグ名なら、`tag/<名前>` を取得してマニフェストのハッシュを得ます
2. マニフェストを取得します。`.cfsenv` に `VerifyKeys` があれば、署名を確かめます
3. 各ファイルの中身を取得して、**ハッシュが合うかを確かめてから**、復号・展開し、出力先に書き出します。既にダウンロード済みの中身は手元のキャッシュから使います

更新がなければ、通信はタグとマニフェストの取得だけで終わります。

## ダウンロード元

- **アップロード**は、各ストレージの API を使って書き込みます（S3 は認証が必要です）
- **ダウンロード**は、何も指定しなければキャビネットから直接読みます。S3 のバケットは公開しなくて構いません
- 認証情報を持たせられない相手（ゲームのクライアントなど）に配るときは、CDN などで HTTP(S) で公開し、その URL をダウンロード元（`Url`）に指定します

詳しくは [ストレージ](storage-backends.md) を見てください。

## 圧縮と暗号化

ファイルは、アップロードするときに **zlib で圧縮 → AES-256-CTR で暗号化** されます。ストレージにも、手元のキャッシュにも、その状態で保存されます。ダウンロードしたときに自動で元に戻すので、使う側は普段意識する必要はありません。

暗号化しても、同じ鍵で同じ中身なら同じデータになるので、重複の排除はそのまま効きます。

設定と、どのファイルが対象になるかは [設定](configuration.md#圧縮と暗号化) を見てください。

## 改ざんの検出

- 中身は、ダウンロードしたときに**ハッシュで照合**します。キャビネットや経路の途中で書き換えられていれば、エラーになります
- マニフェストに**署名**しておけば、マニフェストごと差し替えられても検出できます。マニフェストが正しければ、そこに書かれたハッシュで中身も確かめられるので、全体が守られます。設定は [設定](configuration.md#マニフェストの署名) を見てください

## 古いデータの掃除（`cfs gc`）

どのタグからも、保持期間（既定 30 日）内のマニフェストからも使われていない中身とマニフェストを、キャビネットから消します。消すのは「2回続けて消す候補になったもの」だけで、マニフェストを消してから、その中身を後の回で消します。詳しくは [コマンド](commands.md#gc) を見てください。
